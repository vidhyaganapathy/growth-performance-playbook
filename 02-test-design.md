# 02 · Test design

Every test ships with a hypothesis, a spend cap and the number that ends it. **No zombie campaigns.**

## Test card

Fill this in before launch.

```
Test name:
Channel:
Hypothesis: If we [change], then [metric] will [improve] because [reason].
Variable being tested (one only):
Control:
Primary metric: (e.g. cost per qualified lead)
Secondary metrics: (e.g. CTR, landing page conversion rate)
Budget / spend cap:
Duration:
Kill rule:
Scale rule:
Owner:
```

## Good vs bad hypotheses

| ❌ Vague | ✅ Testable |
|---|---|
| "Let's try video" | "A 15s creator video will lower cost per qualified lead vs static, because it explains the product faster" |
| "Test new audience" | "A company-list audience will raise lead qualification rate vs job-title targeting" |

## Kill and scale rules

| Rule | Example |
|---|---|
| **Kill: spend cap** | Spend reaches 2–3× target CPL with no leads |
| **Kill: quality** | Leads come in but fewer than [x]% qualify |
| **Kill: time** | No signal after the planned duration |
| **Scale** | Beats target cost per qualified lead for a full week |

Set the numbers from your own account benchmarks.

## Prioritising tests

Score each idea 1–5 on:
- **Impact:** how much could it move cost per qualified lead?
- **Confidence:** how sure are we it'll work?
- **Ease:** how quickly and cheaply can we run it?

Run the highest totals first.
